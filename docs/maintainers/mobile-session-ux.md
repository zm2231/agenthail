# Mobile session experience

September 12, 2026. This audit supersedes the September 7 local layout verdict. The physical-device audit reproduced a session-list tap that did not navigate and an empty nested turn-duration card. Passing model tests and inspecting a fixture had not covered that user path.

**The maintainer rejected the physical-phone experience after installing 0.2.23 (34).** CI and release checks passed, but those receipts did not establish acceptable usability. The reading, queue-expiry and model-catalog repair has local verification; release and installed-phone verification remain separate gates. Do not treat the local review verdict below as approval of the installed experience.

The installed build exposed oversized Markdown headings, repository instructions occupying the chat, raw identifiers in untitled session headers, and inadequate reading hierarchy. The live queue capture contained 40 dead rows, all past their recorded expiry, still presented as current delivery decisions. Claude model discovery returned a fixed three-option list. These are concrete follow-up defects, not simulator or mirroring explanations.

The [research comparison](../research/mobile-agent-clients-2026-09.md) records pinned source inspection for Happy, HAPI, Mimi, Agent Phone and Inkbox, plus the maintainer’s concrete ChatGPT Remote and Claude mobile references. [Native design](../../native/DESIGN.md) records the resulting interaction choices. The minimum version is deliberately iOS/iPadOS 18 for Textual 0.5.0.

Sessions, Inbox and Settings have distinct jobs. Sessions groups by reported workspace and offers Running, Recent and All. Recent follows the host’s current-session catalog; it is not a chronological “today” feed. Inbox contains delivery work and history. Past-expiry failed deliveries belong in history even when their outcome was never confirmed. An inflight attempt remains current until it finishes.

## September 12 reading and runtime repair

The next candidate opens long conversations at the latest work. Scrolling back stops following; returning to the bottom or using Jump to latest resumes it. Setup instructions open from compact document rows, long user messages open in full on demand, and All events retains the recorded sequence. Assistant prose uses body-sized serif text, headings capped at 1.4 times body size, and unfilled inline monospace. Transcript, summary and composer share a 600-point maximum width. Normal dark/light phone captures and normal iPad capture received an independent visual accept; this remains distinct from the maintainer's installed-phone acceptance.

`Registry.ListQueue` and `ListAttentionItems` classify expired dead rows as historical and resolve old attention entries. They preserve unknown delivery outcomes. The API exposes `historical`, `expiresAt` and `deliveryOutcome`; Inbox and the latest instruction receipt consume them. The original queue capture contained 40 dead rows, all expired. Regression coverage includes inflight attempts past TTL, unexpired unknown outcomes, known failures, and delivered status with stale error text. Sending again is always explicit.

Claude discovery uses the installed CLI's stream-json `initialize` control response, without a user prompt. A 15-second deadline, process-group cleanup, coalesced requests and a one-minute successful-result cache bound discovery. Errors remain retryable. Codex discovery preserves paginated runtime options and reported reasoning efforts. The parent’s direct source probe (`go run ./build/verify-model-catalog.go`, ignored `build/live/runtime-model-catalog.json`) returned six Claude choices in 661 ms and eleven Codex choices in 5 ms. Claude included `default`, `opus[1m]`, `claude-fable-5-1[1m]`, `sonnet`, `haiku` and `claude-opus-4-8[1m]`; this is a local catalog receipt, not a guarantee that every choice can execute on every account.

Creation, composer and inspector use the same searchable picker with an explicit Apply action and retryable loading errors. Codex effort and work/plan mode are per-session drafts for normal instructions; steering preserves the draft and uses the active turn. A failed send retains its settings, and a successful send cannot erase settings edited while the request was in flight. Schema editors and service-tier controls are intentionally absent from the phone.

Session history, activity, context, goal and model reads run concurrently under one 20-second request deadline. The native request timeout is 25 seconds. A history timeout can return an explicit warning alongside independently retrieved activity and metadata. `session_model_metadata_test.go` verifies both metadata survival and a shared deadline across slow providers.

Current local receipts: `reading-go-race.log` records the full Go race suite; `reading-vet.log`, `reading-macos.log`, `reading-project.log` and `reading-copy.log` record vet, ad-hoc Mac build, generated project and public copy checks. Native `reading-tests-4.xcresult` passes 33 unit tests and seven existing UI journeys; its remaining fixture/query failures are resolved by `reading-tests-5.xcresult`, which passes all three turn-setting flow tests and all three model-picker journeys. The additional `reading-tests-6.xcresult` passes Codex creation payload and cross-agent option isolation, bringing coverage to 37 unit tests and ten UI journeys. The final targeted run verifies sparse payloads, failed-send preservation, new-draft preservation during refresh, search selection, explicit custom selection and catalog-error retry. `reading-release-device.log` records the Release build for a physical iOS device. Full GitNexus change analysis (`reading-graph-full.json`) contains 378 symbols and 20 affected flows with no partial or truncated result; its aggregate risk is critical. Shared queue and API paths received focused behavioral checks and independent review. Private screenshots and runtime captures stay in ignored `build/`.

[CI at `b26a23c`](https://github.com/zm2231/agenthail/actions/runs/34679387711) subsequently passed all 37 native unit tests and ten UI journeys in one run, plus Go race tests, vet, native builds and installer checks. [Release 0.2.24 (35)](https://github.com/zm2231/agenthail/actions/runs/34680238808) completed internal TestFlight delivery. Installing its signed Mac package changed the live snapshot from 40 stale attention entries to zero, and returned eleven Codex models with effort metadata. The shell-based source probe had not covered that environment.

The executable-selection follow-up shares resolution across Claude catalog and lifecycle operations and persists an explicit binary in launchd configuration. Its native-install regression exercises both paths with `/usr/bin:/bin` as PATH. The actual initialize-only probe using the installed daemon's PATH returned six Claude choices in 913 ms; no model instruction was sent. `claude-install-race.log`, `claude-install-vet.log` and `claude-install-upgrade.log` record full Go race, vet and installer checks. Installed verification of that follow-up remains a release gate.

Tool runs do not cross message or lifecycle boundaries. A collapsed summary can read “3 commands, 2 file reads (1 failed)”. Individual calls retain the original input, full recorded output and IDs. “No result yet” does not assert execution is still running. All events preserves raw order rather than the paired inspection order. Stop and steer are capability-derived; the composer does not call a steer operation “queue after this turn”.

## Distribution and operational boundaries

[The TestFlight runbook](testflight.md) documents signing, App Store Connect access, internal tester management, diagnostics and GitHub release automation. A `v*` tag starts the release workflow; ordinary main builds do not upload to TestFlight. The workflow also publishes the Mac package and deploys the relay. A UI source commit alone does not update the phone or the running Mac daemon.

The repair introduces no daemon restart, model instruction, pairing replacement or notification registration during local verification. Physical inspection of the old installed app and rendering captured data establish different facts. A corrected TestFlight build and the actual paired phone path require a separate release/install receipt.

## Remaining capability boundaries

This release identifies images but does not retrieve their pixels; a placeholder does not match the reference gallery. Live approvals, structured question replies, subagent navigation, artifact browsing and authoritative repository diff review need explicit supported contracts. Recorded permission tools are not live permission requests. The voice operator has a separate implementation and live-audio verification task; no inert microphone control is shown here.

Pages remain bounded to approximately 512 KiB, up to 200 items, a 4 MiB read window and 16 KiB per text item. JSONL is expected to be append-only. A cursor beyond a shortened file returns a refresh error. An adapter schema change may require parser work. An open session refreshes every four seconds plus event updates, with explicit stale/error states. A stale but readable catalog does not block connecting to the live event stream; StaleConnectionTests covers that recovery boundary. VoiceOver end-to-end, real push delivery and a fresh camera pairing round trip are outside this repair’s completed local checks.
