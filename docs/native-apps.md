# Agenthail on Mac and iPhone

Agenthail includes a Mac app, a menu bar shortcut, and an optional iPhone companion. The browser dashboard remains available too.

## Mac app

The Mac app keeps your connected conversations in one window.

- **Sessions** sit in the sidebar, grouped by Mac workspace, with **Running**, **Recent**, and **All** (⌘1, ⌘2, ⌘3). Sessions that need you appear first. Search (⌘F) filters the list; typing at least three characters also searches older Codex history. A session's subagents nest under it, collapsed until you open the chevron or select one; the parent row shows how many subagents it has and how many are working, and the filter counts count each family once. The filter button next to New Session narrows the list by status (working, idle, offline, unavailable) and by surface; the active filters show under the search field and each one clears with a click.
- **Conversations** open at the latest work. You can send, steer, stop (⌘.), and jump to latest (⌘L). ⌘↩ queues a message while an agent works and ⌥⌘↩ steers the running turn; Settings can swap the two for every Agenthail app, including your iPhone. When a message would queue, **Steer now** sends it into the running turn instead. Codex sessions can set effort and Plan or Work mode for the next message from the slider button under the message box. Typing `/` lists the commands the session supports: `/name`, `/compact`, `/stop`, `/steer`, `/model` and `/goal` do what the matching buttons do, and Return completes a partly typed command. Drafts belong to their session. Files and images dropped on the message box or picked with the paperclip are listed above it, where each can be removed; a folder can't be attached. Sending uploads them to the computer that runs the session, so they reach agents on a paired host too: images go to the agent as images, and other files as their stored paths, shown in your message as file chips.
- Each tool call is one quiet line, such as **◆ Run swift test** or **◆ Read App.swift**; click a line to see its input and recorded output; an edit, write or patch shows what it changed as a unified diff instead, with removed lines in red, added lines in green and the words that changed marked. A run of more than six calls folds into one line, such as **Ran 8 commands and read 2 files**, that expands to the individual lines. An open run ends with **Collapse activity** and an open line with **Collapse tool**, which fold it and scroll back to its first line. Files the run edited appear as chips with lines added and removed; click a chip to see that file's diff for the run. A failed call is the only coloured line and opens on its own to show its error output. Long output starts as a preview; **Show all** lays it out 500 lines at a time, with **Show less** at the bottom to return to the preview, and **Copy output** copies the recorded text. A tool with no recorded result says **Running** while its turn is still going, **Interrupted before a result** or **The turn failed before a result** when its turn ended that way, and otherwise **No result recorded**; a result recorded after other activity says **Result recorded further down**. Its input reads as the command followed by each field, rather than raw JSON. Rows you open stay open when you switch to another session and back. Reasoning summaries appear as **Thought** lines in the run they belong to, and events such as context compaction show as a divider. Your messages sit on the right with their time and, on hover, **Copy** and **Edit**. A message another agent sent is one muted row: the agent's name, then the message in italics, cut to two lines. **Show more** opens the whole message, its files, time and **Copy**; a message that fits in two lines has no **Show more**. A background task's notification shows the same way, with its status. When this session sends to another agent, the send is an indented line under the reply, such as **“Tests pass” → @collab**, with **failed** if it was not delivered; click it to read what was sent. Two or more agent messages or notices in a row fold into one line, such as **3 messages from agents** or **3 updates · 2 agent messages, 1 task notice**, unless they are the newest items in the transcript. **View > Expand Agent Messages** (⌥⌘E) opens every one and stops folding. Each agent reply starts with a small mark; the reply that ends a turn closes with **Finished** and how long the turn took, the time, and **Copy** on hover.
- Text in messages and replies can be selected and copied. Under each message, **Copy** copies the whole message as Markdown, and **Edit** on your own message opens it in place; **Send** posts the edited text as a new message in the same session. A message that fails to send stays in the transcript marked **Not sent** with its attachments; **Retry** repeats the same request, and **Edit** sends the edited text with the same attachments.
- The **inspector** (⌥⌘I) shows a session's details, context usage with a token breakdown, and delivery work, switches its model or compacts its context when the agent supports it, and lets you set, edit, pause, budget, or clear its goal when the agent supports goals. Codex sessions fork in one click from the inspector or **Session > Fork**; the fork opens in the same folder, and the inspector lists Codex's own queue for the session, where you can add, edit, reorder, delete, or start queued input. Claude Code sessions started with `claude --bg` show their background status and logs there, with Stop and Resume; sessions the Claude host runs show their status, with Stop and Resume. When Agenthail can't confirm whether a fork, queue change, Stop or Resume went through, trying the same action again checks on that request instead of repeating it. Once you reload the queue or check Status, the next try is new work. A fork that may still be in progress says so under the message box, with **Fork again** to start another. Its **Subagents** section links to the parent of a subagent, lists Codex subagents you can open, and lists Claude Code subagents with their type, task and working state.
- **New Session** (⌘N, or ⌘T and **+** in the tab bar when tabs are on) opens in the window, starting with the first message. Under it, menus pick the agent (Claude, Codex, or Notion), the computer it starts on, the project (the host's recent projects by name, or **Choose…** for any folder), where it runs, and the model. The model menu lists the agent's models and the effort each one supports; a session started in a terminal uses the model but the agent's own effort. If the models can't load, New Session says why and the session uses the runtime default. While the app can't reach Agenthail, you can still write the message and start it once Agenthail is back. When Agenthail can't confirm a session started, starting the same session again checks on that request instead of repeating it; **Start again** starts a new one.
- **Projects**: the folder button at the top of the sidebar adds a project: choose the computer, pick one of its folders that isn't a project yet or type one, and optionally name it. Adding a folder that is already a project changes nothing. Right-click a project for **Rename…** (the name applies on every computer where it was added), **New Conversation** in each of its checkouts, **Set Lead…** or **Change Lead…** to start a lead conversation, **Clear Lead**, and **Remove** for each computer it was added on. Right-click a session for **Add Folder as Project**, including sessions on another computer, and **Make Project Lead**. When the project already has a lead, the app asks before replacing it. Projects you added that have no sessions yet are listed under Recent and All.
- **Tabs** in the title bar hold the sessions you have open, unless `titlebar.tabs = none` turns them off. Clicking a session in the sidebar opens it in a preview tab, shown in italics, that the next click replaces; sending a message, double-clicking the tab, or **Keep Tab Open** keeps it. ⌘T opens a New Session tab, ⌘W closes the tab, and ⌃Tab, ⌃⇧Tab, ⌘⇧] and ⌘⇧[ move between tabs. Closing the last tab leaves a New Session tab. Archiving a session closes its tab and shows **Unarchive** for a few seconds; if unarchiving fails, the notice stays with the reason and **Try Again**.
- The **status strip** along the bottom shows Claude and Codex usage limits, how many sessions are working and need you (click to open the first), the computers Agenthail is connected to, and **Terminal**, which brings the open session's terminal forward. Codex usage is the account's limits as the newest Codex rollout on this computer recorded them, so it is only as fresh as the last Codex turn: a reading more than an hour old shows its age (`19% · as of 3h ago`), and a window whose reset has passed shows nothing until Codex runs again.
- **Appearance** (theme, accent, background, glass, tabs and status strip) comes from `ui.conf`. See [Appearance with ui.conf](ui-conf.md).
- **⌘K** opens a command palette for jumping to any session, starting a new one (⌘N), and session actions.
- The **Session** menu holds Go to Session (⌘K), Rename, Open in New Window, Fork, Talk to Orchestrator, Call This Session, and Stop (⌘.); the **View** menu switches between Running, Recent, and All and shows or hides the inspector. They act on whichever Agenthail window is in front.
- Any session can open in its own window from its context menu or the palette, and can be renamed there or from the inspector. A name another session already uses is refused. Windows showing the same session share its draft.
- A session that disappears from the host stays readable with a notice until you close it.
- **Voice**: the waveform button in the sidebar footer, the menu bar item, or **Session > Talk to Orchestrator** opens the Voice window. The waveform button in a conversation's header, or **Session > Call This Session**, opens it routed to that session. See [Codex Voice orchestrator](#codex-voice-orchestrator).
- A session the Claude host runs that waits on a tool approval or a question shows the request above the message box: **Allow**, **Always allow** when Claude offers it, and **Deny** for an approval, or the question's options, an **Other answer** field and **Answer**. The inspector's **Permissions** menu changes how the session asks. The notification for that request shows what it asks, the first question when there are several. An approval gets **Allow**, **Always allow** when Claude offers it, **Deny**, and **Deny with message…**, which sends what you type as the reason. A single question that takes one answer gets a button for each option and **Reply…**, which answers in your own words. A notification answer is one choice or one line of text, so several questions, or one that takes several answers, have no buttons: open the notification and the session shows the request above the message box. A button answers the request as it is when you press it, so one from an older notification never answers something you did not see. If the request was already answered, the app says so.
- When an agent finishes, its notification opens that session. Subagents and one-off Codex runs send no finish notification; when one waits on you, its notification opens the conversation that started it. **Reply** on the notification sends your answer to the session; if it can't be sent, the app opens the session with your reply in its draft.
- **Send to Agenthail** in any app's Services menu adds the selected text to the open session's draft, or opens New Session with it filled in. Nothing is sent or started until you do it.
- Every keyboard shortcut can be changed or cleared in Settings > Keyboard, which also sets a shortcut that opens the session palette from any app. The shortcuts listed here are the defaults.
- Spotlight finds sessions by name and folder; choosing one opens it in the app. Settings can turn this off.
- Links open the app from anywhere: `agenthail://session/<id or @handle>` opens a session, `agenthail://new` starts one, and `agenthail://open` brings the app forward.

The Dock icon shows how many sessions need you. The menu bar item and the Dock icon's menu list sessions that need you, sessions that are working, and the most recently active idle sessions. The menu bar item also opens the app, a new session, or Settings.

Settings opens on an **Overview** of each surface: its health, how many sessions are working, current, and queued, what is wrong, and a button that runs the fix when Agenthail knows one. General holds the connection and service controls, the local listener address, and how long Codex threads stay in Recent (presets from 1 to 24 hours, and any saved window up to 168 hours stays selectable). Devices pairs an iPhone and, while phone access is on, copies the private browser link or shows it as a QR code that hides itself after a minute. Delivery lists waiting messages, the most recent delivery outcomes, and automatic handoffs, which can run every time or once. Notifications and recent activity have their own tabs.

Agenthail updates the app, command line tool, and background service together. If parts of an installation ever fall out of sync, the app asks you to update instead of attempting an unsafe action.

## iPhone app

The iPhone and iPad app requires iOS/iPadOS 18 or later. It pairs with any computer running Agenthail and reaches it, and the hosts paired with it, privately through Tailscale. It does not make any of them public on the internet.

Its theme, accent, background and glass come from `ui.conf` on the first computer it paired with, and change when that file changes. The sessions list shows the background with each session on glass; a session, Settings and Inbox read on a tinted pane. Behind text, the tint deepens until text reaches the contrast `ui.conf` asks for (7:1 with Increase Contrast). Where the text colours can't reach it, the surface turns solid, which is the most contrast they get. Reduce Transparency, or `glass = off`, gives plain system surfaces. See [Appearance with ui.conf](ui-conf.md).

[Request TestFlight access privately](mailto:zainmer@protonmail.com?subject=Agenthail%20iPhone%20TestFlight%20access&body=Please%20invite%20this%20Apple%20Account%20email%3A%20). An App Store distribution `.ipa` cannot be installed directly on an ordinary iPhone, so GitHub release downloads are not used for the companion app.

To connect it:

1. Install Tailscale on the iPhone and on the computer running Agenthail, and sign both into the same account.
2. Turn on phone access: run `agenthail dashboard remote`, or turn on **Phone access** in the Mac app's Settings > **Devices**.
3. Show a pairing code on that computer, any one of these ways:
   - Run `agenthail devices pair` in a terminal, including over SSH. It draws the code, prints the link, and waits until the phone pairs.
   - In the web dashboard, open Settings > **iPhone app** and choose **Pair an iPhone**.
   - In the Mac app, choose **Show Pairing Code** under **Pair an iPhone**.
4. Scan the code with the iPhone's camera or with **Scan pairing code** in the Agenthail app. A web dashboard open on the iPhone offers **Open in Agenthail** instead.

The pairing code expires after five minutes and works once. You can disconnect a phone from either device: in the app's Settings, in the web dashboard, in the Mac app, or with `agenthail devices remove <device>`.

The app can pair with several computers. To add one, open Settings > **Add a computer** and pair as above; scanning a code from a computer that is already paired reconnects it instead of adding it again. Sessions from every paired computer appear in one list, each marked with the computer it runs on. A session stays usable while any computer that lists it can be reached: when the phone can't reach the computer that runs it, the app works with the session through another paired computer that has that computer paired as a host. Settings shows each computer's connection, surfaces and notifications, with **Reconnect** and **Remove**.

On iPhone, **Sessions** is the place to find, start, and continue work. **Inbox** separates current delivery decisions from completed instructions. **Settings** manages the connection and notifications.

Tap **+** in Sessions to start work with a configured Claude, Codex or Notion runtime. Choose one of the host's projects by name or enter an existing folder for Claude/Codex, optionally choose a model, and write the first instruction. Runtime permission defaults remain in effect unless you change the Claude permission setting; approvals may require attention on that computer. If creation cannot be confirmed, check the agent catalog on that computer before retrying. A returned session with uncertain first-instruction delivery opens with that uncertainty visible.

Touch and hold **+** in Sessions, then choose **Add project** to add a project on any paired computer, from its folders that aren't projects yet or a folder you type. Touch and hold a project's header for **Rename…**, **New conversation** in each checkout, **Set lead…** or **Change lead…**, **Clear lead**, and **Remove** for each computer it was added on. Projects with no sessions yet are listed under **Projects without sessions** in Recent and All; tap one for the same actions. A session's details offer **Add folder as project** and **Make project lead**. When the project already has a lead, the app asks before replacing it.

Claude creation opens the session in Agenthail's [Claude host](maintainers/claude-host.md) and sends your message as its first turn. Expand **Claude options** to choose a session name, new worktree, named agent, effort or permission mode. Successful registration does not mean the first turn is complete. A session the host runs has no Remote Control, so it is not listed in claude.ai or the Claude apps. Its tool approvals and questions wait for you; answer them in the dashboard or with `agenthail answer`. See [session operations](maintainers/session-operations.md) for lifecycle controls available through the CLI and dashboard.

Session details preserve recent Claude Code and Codex activity from local transcripts: messages, commentary, tool calls and results, available reasoning summaries, and compaction events. Assistant messages render Markdown, including code blocks and tables. Message text can be selected. Touch and hold a message to copy it, or touch and hold your own message and choose **Edit and resend** to put it in the message box. Each tool call is one quiet line, such as **◆ Run swift test** or **◆ Read App.swift**; tap a line to see its input and recorded output; an edit, write or patch shows what it changed as a unified diff, with the words that changed marked. A run of more than six calls folds into one line, such as **Ran 8 commands and read 2 files**, that expands to the individual lines. Files the run edited appear as chips with lines added and removed; tap a chip to see that file's diff for the run. A failed call is the only coloured line and opens on its own. Long outputs begin with a bounded preview; **Show all** lays out the rest 500 lines at a time, and **Copy output** copies the recorded text. A missing result is labeled **Running** only while the call's turn is still going; once the turn has ended it reads **Interrupted before a result**, **The turn failed before a result** or **No result recorded**, and a result recorded after other activity reads **Result recorded further down**. The reply that ends a turn shows how long the turn took, such as **Finished 1:55**. A message from another agent, or a background task's notification, is one row with the sender and the first two lines; tap **Show more** to read all of it. Sends to other agents are indented lines such as **“Tests pass” → @collab**, and tapping one shows what was sent. Two or more agent messages or notices in a row fold into one line that opens to list them, except for the newest items. **Expand agent messages** in the session menu opens them all. Events appear as dividers. Lines you open stay open when you switch sessions and come back, until the app quits.

The session menu offers **Chat**, which pairs tools with results within message boundaries, and **All events**, which shows original record order. Reasoning reads as a **Thought** line. **Load older activity** pages backward. Reading older content pauses automatic scrolling; **Jump to latest** resumes it.

The session menu or compact header opens context usage, reported token breakdowns, goal, model, workspace, connection source, and supported controls. Status, model and context remain in the compact header. Drafts belong to individual sessions. The rounded composer offers model selection, steering and stop when supported. Its **Latest instruction** receipt follows that instruction’s delivery outcome and opens the session inbox, where earlier instructions remain visible. An interrupted send remains explicitly unconfirmed; check the transcript before retrying.

Session details also let you name a session and set, edit, or clear a supported goal. **Session inbox** shows that session's delivery work. Inbox **Current** contains waiting/sending instructions and delivery attempts needing review. **History** contains up to the latest 100 completed, canceled or older failed instructions across sessions. Sending again requires a delivery decision; it is never an automatic retry of an uncertain attempt. Pending or failed instructions can be canceled or dismissed. Each pending instruction shows how long it has waited and what holds it: the agent is working, waiting on you, offline, or about to retry. A session that asked you a question or needs an approval shows **Waiting on you**, and its messages wait until you answer. A Claude CLI in a terminal can be answered here once `agenthail hooks install` has run; its prompt shows the same buttons as any other request, and an answer given in the terminal first withdraws the notification. When Agenthail can't answer the prompt, as for a terminal Claude without the hook or a Codex request for input, a card above the composer names the agent, says whether it asks a question or needs your input or approval, and says where to answer it, with **Open in cmux** or **Open in tmux** when the terminal can be focused, and the composer does not offer a steer. A Claude session between turns whose background tasks still run, such as a background shell or an asynchronous agent, shows **Waiting on background work**, and its details list the tasks, with ambient ones such as file watchers marked; the finished alert waits until that work is done. Instructions already in flight cannot be canceled from Inbox.

Sessions groups work by its full reported Mac workspace, nesting descendant workspaces beneath the nearest visible parent while preserving each complete path, with a working indicator on active sessions. A session's subagents nest under it behind a **Show subagents** row, and the parent shows its subagent and working counts; Running counts families, not subagent threads. Workspace sections expand and collapse independently. It offers **Running**, **Recent**, and **All**. Recent follows the host's current-session catalog; All includes saved sessions. Searching with at least three characters also queries older Codex history. Notification links resolve the target directly even when it is absent from the current list. On iPad, the session list and selected session sit side by side at normal text sizes. Accessibility text sizes use a single column and stacked composer controls.

Activity is read in bounded pages: up to 200 items and roughly 512 KiB of encoded items per page, with a 4 MiB local read window and 16 KiB per text item. Oversized records/output are marked as shortened. Images are identified but must be opened in the original agent app. When local activity is unavailable, the app displays available message history and explains the limitation. Reading a recorded permission or question tool does not approve it; only a session the Claude host runs, or a terminal Claude whose prompt Agenthail's hook holds, takes live approval and question answers, shown above the message box as on the Mac. An open session's state (name, alias, status, what it waits on, what it can do, read-only, workspace, connection and runtime) follows the catalog while it stays open. There is no file browser. An open session refreshes activity every four seconds in addition to event-driven updates.

Agenthail only offers message controls when it knows a conversation is writable. Older Codex history can still be read, but it will not show a composer.

## Codex Voice orchestrator

With a voice-enabled host, **Talk to orchestrator** on the Mac or iPhone opens
a conversational Codex Voice call. Ask about your agents, discuss a plan, or ask
the orchestrator to create an agent and send it work. It uses one persistent Codex
Desktop thread with the packaged Agenthail Operations skill, not on-device
dictation. Your Codex account must support native Voice, and a paired phone must
have control permission. With several computers paired, Settings > **Voice**
chooses which one runs the orchestrator.

Live conversation and agent activity remain visible. **Open full timeline**
opens the same ordinary session. Enter a session ID or alias to route the call to
that exact session; during a call, **Transfer to session** moves it there,
**Return to orchestrator** moves it back, and **Stop selected session** stops
that session's running turn without hanging up. **Hang up** ends audio, not agent
work; closing the Voice window on the Mac also ends the call. Call again to
resume the same orchestrator. Native approvals may still need attention on your
Mac.

On iPhone the call is a system call: it shows in the status bar and the
Lock Screen call controls, and it keeps going when you close the Voice screen,
switch apps or lock the phone. **Return to call** reopens it. Hang up in the app
or with the system call controls; force-quitting the app ends the call.
While the microphone is muted or the call is on hold, nothing you say is sent
as a request and the operator cannot move the call or message a coordinator.

The Mac asks for microphone access on the first call. If access is off, the Voice
window says so and **Open System Settings** goes to Privacy & Security >
Microphone. Only one device holds a call at a time; another device's call shows
as in use until it hangs up there.

See [Voice setup, capabilities, and verification](maintainers/codex-voice.md).

## Notifications

Notifications are optional. Agenthail can tell you whether a Claude Code, Codex, or Notion agent finishes or fails without putting the agent name, conversation title, or conversation text in the alert. Tapping an alert opens the related conversation.

When a session the Claude host runs waits on a tool approval or a question, the alert says only that the agent is waiting on you and names the request by an opaque ID. Before iOS shows it, Agenthail's notification service asks your paired computer for that request directly over Tailscale, within five seconds, and the alert then shows what is asked, with the same buttons as on the Mac, including **Reply…** or **Deny with message…** to type an answer. Several questions, or one that takes several answers, show the first question and no buttons; tapping opens the session at the request. If that computer can't be reached in time or the request is no longer open, the alert arrives as it was sent, and tapping it opens the session. A button needs your phone unlocked; the app, not the notification service, sends the answer to your paired computer. If sending fails, a notification says why and repeats what you typed.

Each paired computer registers the phone for its own notifications, and an alert's buttons answer through the computer that sent it. Turning notifications off removes that phone's notification registration from every paired computer. You can also forget a paired computer from the iPhone app if it is no longer available.

## Privacy

Phone access stays inside your Tailscale network. Pairing details are stored securely on each device, and you can revoke a paired phone at any time.

See the full [security and privacy model](../SECURITY.md).
